# 道财榜模拟数据生成规则 V1.0

> 本规则仅用于PRD V2.0演示数据，不代表真实行业统计结论。

## 1. 生成目标

- 读取`data/companies.csv`中的30家合成企业；
- 为每家企业生成2023—2025年连续3年数据；
- 生成90条企业年度数据；
- 生成90条员工福利数据；
- 为每项指标生成来源和状态记录；
- 使用固定随机种子，确保结果可重复；
- 主动制造合理的数据缺失，用于测试披露不足场景。

## 2. 固定参数

| 参数 | 值 |
|---|---|
| 随机种子 | `20261027` |
| 生成器版本 | `synthetic_generator_v1` |
| 年度范围 | 2023—2025 |
| 金额单位 | 人民币元 |
| 比例保存方式 | 0至1的小数 |
| CSV编码 | UTF-8 with BOM |

固定随机种子意味着：在输入企业表和生成规则不变时，每次运行应获得同样的数据。

## 3. 行业基础参数

以下参数是演示模型的起始区间，不是对现实行业的统计判断。

| 参数 | 制造业 | 互联网与软件 | 零售物流服务 |
|---|---:|---:|---:|
| 基准人均营收 | 80万元 | 140万元 | 45万元 |
| 基准净利润率 | 7.5% | 16% | 5.5% |
| 基准人均劳动现金投入 | 14.5万元 | 30万元 | 10.5万元 |
| 基准平均周工时 | 46小时 | 46小时 | 48小时 |
| 基准外包比例 | 18% | 12% | 28% |
| 基准研发投入率 | 4.5% | 15% | 2% |

实际企业数据将在基准值附近波动，并受到企业原型、规模和年度趋势影响。

## 4. 企业规模参数

| 规模 | 基准员工人数 |
|---|---:|
| 小型 | 650人 |
| 中型 | 2,600人 |
| 大型 | 12,000人 |
| 超大型 | 50,000人 |

员工人数在基准值附近波动，并按照企业趋势逐年变化。

## 5. 生成顺序

```text
读取企业主表
  ↓
确定行业和规模基准
  ↓
应用企业原型修正
  ↓
生成员工人数
  ↓
生成人均营收和营业收入
  ↓
生成成本、利润、资产和现金流
  ↓
生成员工现金投入、高管薪酬、分红和回购
  ↓
生成P10收入、中位收入、工时和福利
  ↓
按披露档案制造缺失值
  ↓
写入指标来源记录
  ↓
执行独立校验
```

## 6. 企业原型修正

### 高财富、高分享

- 利润率高于行业基准；
- 人均劳动现金投入高于行业基准；
- 基层收入、社保及休假指标较好；
- 高管差距不显著扩大。

### 高财富、低分享

- 利润率高于行业基准；
- 人均劳动现金投入低于同类高利润企业；
- 员工投入增速低于企业产出增速。

### 低财富、高善待

- 利润率低于行业基准；
- 基层收入和福利高于同等盈利水平企业；
- 股东现金分配相对克制。

### 高薪、高工时

- 人均劳动现金投入较高；
- 平均和P90周工时较高；
- 离职率不因高薪自动降至最低。

### 股东优先型

- 分红及回购比例较高；
- 员工投入增长相对较慢。

### 外包规避型

- 外包比例较高；
- 外包人员待遇相对正式员工较低；
- 正式员工数据可能表现尚可。

### 高管差距型

- 最高薪高管报酬倍数较高；
- 其他员工福利不必然较差。

### 持续改善型及共同成长型

- 三年员工投入、福利和收入指标逐步改善；
- 共同成长型的人均劳动投入增速接近或高于人均营收增速。

### 数据不透明型

- 原始模拟值仍会生成；
- 输出前按较高概率将部分员工福利字段设置为缺失；
- 缺失值不得按0参与评分。

## 7. 三年趋势

| 趋势 | 基本逻辑 |
|---|---|
| `improving` | 营收、员工投入和福利逐步改善 |
| `stable` | 指标小幅增长或保持稳定 |
| `deteriorating` | 营收低增长，员工投入或福利下降 |
| `volatile` | 三年间出现明显正负波动 |

每个年度在趋势基础上加入小幅随机扰动，避免全部企业形成完全相同的曲线。

## 8. 收入与福利关系

### 8.1 人均劳动现金投入

```text
人均劳动现金投入
= 员工现金投入 ÷ 平均员工人数
```

该指标包括工资、奖金、社保、公积金及部分福利的模拟合计，不等于员工平均到手工资。

### 8.2 收入层级

在数据不缺失时必须满足：

```text
基层P10年收入
< 员工收入中位数
< 人均劳动现金投入
```

### 8.3 工时和离职

模型只表达统计倾向：

- 工时越长，离职率通常越高；
- 基层收入越不足，离职率通常越高；
- 社保、休假和员工参与度越高，离职率通常越低；
- 高薪不能完全抵消极端工时；
- 快速扩张可能同时带来招聘和离职增加。

## 9. 缺失数据

按企业`disclosure_profile`控制缺失概率：

| 档案 | 员工福利字段目标覆盖 |
|---|---:|
| 高 | 单个企业年度约88%—100% |
| 中 | 单个企业年度约69%—81% |
| 低 | 单个企业年度约50%—63% |

财务核心字段覆盖率高于员工福利字段。缺失值输出为空字符串，同时在`metric_evidence.csv`标记：

```text
data_origin = missing
confidence_level = not_available
review_status = validated
```

缺失字段按每个“企业—年度”精确控制数量，避免高披露企业因为随机波动意外低于预期范围。生活工资基准和已经设定的重大死亡事故不参与随机缺失。

## 10. 强制逻辑约束

- 营业收入和员工人数必须大于0；
- 营业成本不得为负；
- 分红、回购、税费和研发投入不得为负；
- 所有覆盖率必须在0至1之间；
- P90周工时不得低于平均周工时；
- 正式员工和外包人数不得为负；
- 研发人员和生产人员不得超过正式员工人数；
- 工伤率和重大死亡人数不得为负；
- 所有企业必须保持`is_synthetic=true`。

## 11. 输出文件

```text
data/company_years.csv
data/employee_welfare.csv
data/metric_evidence.csv
```

评分所需的`derived_metrics.csv`和`scoring_results.csv`在下一阶段由评分脚本生成。

## 12. 对外使用限制

- 生成结果不对应真实企业；
- 不可用于投资、求职或消费决策；
- 不可描述为行业调查结果；
- 页面和分享材料必须显示“模拟数据”；
- 模型参数不得宣传为真实行业平均水平。
