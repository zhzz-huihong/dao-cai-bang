# 道财榜数据字典 V1.0

> 适用于PRD V2.0模拟数据版

| 项目 | 内容 |
|---|---|
| 版本 | V1.0 |
| 状态 | MVP执行版 |
| 适用周期 | 2023—2025年 |
| 企业数量 | 30家合成企业 |
| 行业范围 | 制造业、互联网与软件、零售物流与服务 |
| 金额单位 | 人民币元，除非字段另有说明 |

---

## 1. 数据设计原则

1. 所有企业均为虚构企业，不与真实企业一一对应。
2. 所有指标必须带有数据来源类型。
3. 缺失值使用空值，不允许使用0代替未知。
4. 金额字段统一保存为人民币元，不在原始表中混用万元和亿元。
5. 比例字段统一保存为0至1之间的小数，展示时转换为百分比。
6. 年度数据以自然年度为统计周期。
7. 企业财务数据、员工数据和评分结果使用`company_id + year`关联。
8. 模拟数据必须能通过固定随机种子重复生成。
9. 派生指标不得手工填写，应通过计算脚本生成。
10. 原始数据变化后，全部派生指标和排名应能够重新计算。

---

## 2. 通用枚举

### 2.1 数据来源类型 `data_origin`

| 值 | 含义 |
|---|---|
| `public_anchor` | 来自公开资料，仅用于确定行业范围或参数 |
| `synthetic` | 按企业原型和生成规则合成 |
| `derived` | 由其他字段计算产生 |
| `missing` | 主动设置为缺失，用于测试披露不足 |

### 2.2 数据置信标签 `confidence_level`

| 值 | 含义 |
|---|---|
| `demo` | 演示数据，不代表现实事实 |
| `reference` | 仅作为公开参考范围 |
| `calculated` | 通过确定公式计算 |
| `not_available` | 当前无数据 |

### 2.3 数据复核状态 `review_status`

| 值 | 含义 |
|---|---|
| `generated` | 已生成，尚未校验 |
| `validated` | 已通过自动校验 |
| `warning` | 存在非阻断性异常 |
| `error` | 存在错误，不得进入评分 |
| `approved` | 已完成人工复核 |

### 2.4 行业 `industry`

| 值 | 中文名 |
|---|---|
| `manufacturing` | 制造业 |
| `technology` | 互联网与软件 |
| `retail_logistics_service` | 零售、物流与服务 |

### 2.5 企业规模 `size_band`

规模仅用于模拟分组，不代表法定企业划型。

| 值 | 模拟员工规模 |
|---|---:|
| `small` | 300—999人 |
| `medium` | 1,000—4,999人 |
| `large` | 5,000—29,999人 |
| `very_large` | 30,000人及以上 |

### 2.6 地区类型 `region_type`

| 值 | 含义 |
|---|---|
| `tier_1` | 一线城市为主要经营地 |
| `new_tier_1` | 新一线城市为主要经营地 |
| `other_city` | 其他城市为主要经营地 |
| `multi_region` | 跨多个地区经营 |

### 2.7 所有制模拟标签 `ownership_type`

| 值 | 含义 |
|---|---|
| `private_style` | 民营型模拟企业 |
| `public_style` | 公众型模拟企业 |
| `mixed_style` | 混合型模拟企业 |

该字段仅用于演示筛选，不对应现实企业法律属性。

### 2.8 数据完整度档案 `disclosure_profile`

| 值 | 目标覆盖率 |
|---|---:|
| `high` | 85%—100% |
| `medium` | 65%—84% |
| `low` | 40%—64% |

## 3. 企业主表 `companies.csv`

每家企业一条记录。

| 字段 | 类型 | 必填 | 说明 | 约束 |
|---|---|---:|---|---|
| `company_no` | integer | 是 | 展示序号 | 连续1—30，不作为数据库主键 |
| `company_id` | string | 是 | 企业唯一ID | 格式`SYN-行业-序号`，全局唯一 |
| `display_name` | string | 是 | 虚构企业名称 | 不得与知名真实企业相同或高度相似 |
| `industry` | enum | 是 | 行业 | 使用行业枚举 |
| `size_band` | enum | 是 | 企业规模 | 使用规模枚举 |
| `region_type` | enum | 是 | 主要经营地区类型 | 使用地区枚举 |
| `ownership_type` | enum | 是 | 模拟所有制标签 | 使用所有制枚举 |
| `primary_archetype` | string | 是 | 主要企业原型 | 见企业原型清单 |
| `secondary_archetype` | string | 否 | 次要企业原型 | 无则留空 |
| `trend_profile` | enum | 是 | 三年趋势 | `improving/stable/deteriorating/volatile` |
| `disclosure_profile` | enum | 是 | 数据完整度档案 | `high/medium/low` |
| `is_synthetic` | boolean | 是 | 是否为合成企业 | 固定为`true` |
| `description` | string | 是 | 企业简介 | 明确为虚构业务描述 |

主键：`company_id`

## 4. 企业年度表 `company_years.csv`

每家企业每年一条记录。

### 4.1 标识字段

| 字段 | 类型 | 必填 | 说明 | 约束 |
|---|---|---:|---|---|
| `company_id` | string | 是 | 企业ID | 必须存在于企业主表 |
| `year` | integer | 是 | 报告年度 | 2023、2024或2025 |

联合主键：`company_id + year`

### 4.2 财务与经营字段

| 字段 | 类型 | 单位 | 核心 | 允许缺失 | 说明与约束 |
|---|---|---|---:|---:|---|
| `revenue` | number | 元 | 是 | 否 | 营业收入，必须大于0 |
| `operating_cost` | number | 元 | 是 | 否 | 营业成本，大于等于0，一般不高于营业收入的1.2倍 |
| `profit_before_tax` | number | 元 | 是 | 否 | 利润总额，可为负 |
| `net_profit` | number | 元 | 是 | 否 | 净利润，可为负 |
| `total_assets` | number | 元 | 否 | 是 | 总资产，必须大于0 |
| `operating_cash_flow` | number | 元 | 否 | 是 | 经营活动现金流，可为负 |
| `taxes_paid` | number | 元 | 是 | 是 | 支付的各项税费，大于等于0 |
| `depreciation_amortization` | number | 元 | 否 | 是 | 折旧与摊销，大于等于0 |
| `rd_expense` | number | 元 | 否 | 是 | 研发投入，大于等于0 |
| `cash_dividend` | number | 元 | 是 | 是 | 现金分红，大于等于0 |
| `share_buyback` | number | 元 | 是 | 是 | 股份回购，大于等于0 |

### 4.3 人员与薪酬代理字段

| 字段 | 类型 | 单位 | 核心 | 允许缺失 | 说明与约束 |
|---|---|---|---:|---:|---|
| `employee_count_start` | integer | 人 | 是 | 否 | 年初正式员工人数，正整数 |
| `employee_count_end` | integer | 人 | 是 | 否 | 年末正式员工人数，正整数 |
| `employee_cash_paid` | number | 元 | 是 | 是 | 支付给职工及为职工支付的现金，大于0 |
| `highest_executive_pay` | number | 元/年 | 是 | 是 | 最高薪高管年度报酬，大于等于0 |
| `rd_employee_count` | integer | 人 | 否 | 是 | 研发人员数量，不得超过年末员工人数 |
| `production_employee_count` | integer | 人 | 否 | 是 | 生产人员数量，不得超过年末员工人数 |

### 4.4 数据元信息

上述每个核心指标在`metric_evidence.csv`中均应存在对应记录，用于保存数据来源类型、生成方法和复核状态。

## 5. 员工福利表 `employee_welfare.csv`

每家企业每年一条记录。该表主要由合成数据构成。

| 字段 | 类型 | 单位 | 核心 | 允许缺失 | 说明与约束 |
|---|---|---|---:|---:|---|
| `company_id` | string | - | 是 | 否 | 企业ID |
| `year` | integer | 年 | 是 | 否 | 2023、2024或2025 |
| `p10_annual_income` | number | 元/年 | 是 | 是 | 基层P10年收入，大于0 |
| `median_annual_income` | number | 元/年 | 是 | 是 | 员工年收入中位数，大于P10收入 |
| `local_living_wage` | number | 元/年 | 是 | 是 | 模拟当地生活工资基准，大于0 |
| `average_weekly_hours` | number | 小时/周 | 是 | 是 | 建议范围35—65 |
| `p90_weekly_hours` | number | 小时/周 | 否 | 是 | 不低于平均周工时，建议不高于80 |
| `overtime_pay_coverage` | number | 比例 | 是 | 是 | 0—1 |
| `social_insurance_coverage` | number | 比例 | 是 | 是 | 0—1 |
| `housing_fund_coverage` | number | 比例 | 否 | 是 | 0—1 |
| `paid_leave_usage` | number | 比例 | 否 | 是 | 0—1 |
| `turnover_rate` | number | 比例/年 | 是 | 是 | 0—1 |
| `training_coverage` | number | 比例 | 否 | 是 | 0—1 |
| `work_injury_rate_per_1000` | number | 每千人 | 是 | 是 | 大于等于0 |
| `major_fatality_count` | integer | 人 | 是 | 是 | 大于等于0 |
| `contractor_count` | integer | 人 | 是 | 是 | 外包及派遣劳动者人数，大于等于0 |
| `contractor_welfare_ratio` | number | 比例 | 是 | 是 | 外包综合待遇相对正式员工比例，0—1 |
| `employee_voice_score` | number | 0—100 | 否 | 是 | 员工参与和申诉机制模拟得分 |

联合主键：`company_id + year`

### 5.1 必须满足的收入关系

在相关数据均存在时：

```text
p10_annual_income
< median_annual_income
< per_employee_cash_investment
```

其中`per_employee_cash_investment`为派生指标。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `company_id` | string | 是 | 企业ID |
| `year` | integer | 是 | 年度 |

| `generation_method` | string | 是 | 生成规则或公式版本 |

## 7. 派生指标表 `derived_metrics.csv`

所有字段由脚本计算，不手工填写。

| 字段 | 单位 | 公式或说明 |
|---|---|---|
| `average_employee_count` | 人 | `(年初人数 + 年末人数) / 2` |
| `revenue_per_employee` | 元/人 | `营业收入 / 平均员工人数` |
| `net_profit_margin` | 比例 | `净利润 / 营业收入` |
| `per_employee_cash_investment` | 元/人 | `员工现金投入 / 平均员工人数` |
| `labor_cash_intensity` | 比例 | `员工现金投入 / 营业收入` |
| `living_wage_ratio` | 倍 | `P10年收入 / 当地生活工资` |
| `labor_distribution_proxy` | 比例 | 见7.1 |
| `executive_worker_gap_proxy` | 倍 | `最高薪高管报酬 / 人均劳动现金投入` |
| `employee_shareholder_distribution_ratio` | 倍 | 见7.2 |
| `contractor_ratio` | 比例 | `外包人数 /（外包人数 + 年末正式员工人数）` |
| `employee_count_growth` | 比例 | 年末人数同比增长率 |
| `revenue_per_employee_growth` | 比例 | 人均营收同比增长率 |
| `per_employee_cash_growth` | 比例 | 人均劳动现金投入同比增长率 |
| `shared_growth_gap` | 百分点 | `人均劳动现金投入增速 - 人均营收增速` |
| `data_completeness` | 比例 | 已有评分字段数 / 应有评分字段数 |

### 7.1 劳动者分配率代理值

```text
labor_distribution_proxy
= employee_cash_paid
÷（employee_cash_paid
  + profit_before_tax
  + depreciation_amortization
  + taxes_paid）
```

若分母小于等于0，则该指标记为缺失并产生警告。

### 7.2 员工与股东分配比

```text
employee_shareholder_distribution_ratio
= employee_cash_paid
÷（cash_dividend + share_buyback）
```

若现金分红和回购均为0，不计算该比值，单独标记为`no_shareholder_cash_distribution`。

### 7.3 高管员工差距代理值

该指标的分母是人均综合劳动现金投入，不是员工中位工资。因此对外必须使用“高管员工差距代理值”，不得称为“CEO与员工中位薪酬比”。

## 8. 评分结果表 `scoring_results.csv`

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `company_id` | string | - | 企业ID |
| `year` | integer | 年 | 年度 |
| `wealth_creation_score` | number | 0—25 | 财富创造质量得分 |
| `income_adequacy_score` | number | 0—15 | 基层收入充足度得分 |
| `labor_distribution_score` | number | 0—12 | 劳动者分配得分 |
| `internal_gap_score` | number | 0—10 | 内部收入差距得分 |
| `benefits_score` | number | 0—10 | 福利保障得分 |
| `hours_safety_score` | number | 0—8 | 工时与安全得分 |
| `development_dignity_score` | number | 0—5 | 发展及职业尊严得分 |
| `responsible_governance_score` | number | 0—15 | 责任治理得分 |
| `red_flag_deduction` | number | 0—100 | 模拟红线扣分，保存正数 |
| `overall_score` | number | 0—100 | 综合得分 |
| `data_completeness` | number | 0—1 | 数据完整度 |
| `ranking_eligible` | boolean | - | 是否达到模拟排名门槛 |
| `industry_rank` | integer | 名 | 行业排名 |
| `overall_rank` | integer | 名 | 综合排名 |
| `score_version` | string | - | 评分模型版本 |

综合得分：

```text
overall_score
= max(0,
    wealth_creation_score
  + income_adequacy_score
  + labor_distribution_score
  + internal_gap_score
  + benefits_score
  + hours_safety_score
  + development_dignity_score
  + responsible_governance_score
  - red_flag_deduction)
```

数据完整度低于70%的企业，`ranking_eligible=false`，进入演示观察组。

## 9. 数据缺失规则

1. 空值代表未知或未披露。
2. `0`只用于确定为零的事实，例如未发生股份回购。
3. 缺失字段在证据表中仍需建立记录，并标记`data_origin=missing`。
4. 缺失字段不直接获得0分，也不自动获得满分。
5. 依赖缺失字段的派生指标同样记为空。
6. 页面显示“暂无数据”，不能显示为“0”。
7. 数据完整度不足70%的企业不参加模拟正式排名。

## 10. 自动校验规则

### 10.1 阻断性错误

- 企业ID不存在或重复；
- 同一企业同一年度记录重复；
- 营业收入小于等于0；
- 员工人数小于等于0；
- 覆盖率不在0至1之间；
- P10收入大于等于中位收入；
- P90周工时低于平均周工时；
- 研发或生产人员超过年末正式员工人数；
- 分红、回购、税费或外包人数为负；
- 工伤率或死亡人数为负；
- `is_synthetic`不为`true`。

### 10.2 警告性异常

- 净利润率绝对值超过50%；
- 员工人数一年变化超过50%；
- 营业收入一年变化超过100%；
- 人均劳动现金投入一年变化超过50%；
- 平均周工时低于35小时或高于65小时；
- P90周工时高于80小时；
- 高管员工差距代理值超过100倍；
- 外包比例超过70%；
- 员工现金投入高于营业收入；
- 中位收入高于人均劳动现金投入；
- 三年趋势与企业预设原型明显矛盾。

警告不一定表示错误，但必须进入人工复核清单。

---

## 11. 显示规范

- 金额小于1万元时显示元；
- 1万元至1亿元之间可显示万元；
- 1亿元及以上可显示亿元；
- 比例保留1位小数；
- 分数保留1位小数；
- 排名显示样本数，例如`3/10`；
- 所有企业卡片显示“模拟企业”；
- 所有数据页显示“演示数据，不对应真实企业”；
- 合成字段不使用“真实”“调查发现”等措辞。

---

## 12. 版本管理

每次修改字段或公式必须更新：

- 数据字典版本；
- 数据生成规则版本；
- 评分模型版本；
- 数据集生成时间；
- 固定随机种子；
- 变更说明。

评分结果必须保存`score_version`，防止不同公式生成的排名被混用。
